# YAM v2 в DARKLS Alice Panel 0.4.0

1. В панели открой «Обновления панели», проверь и установи 0.4.0. После перезапуска обнови страницу.
2. Открой «YAM v2» → «Установить актуальный YAM». На момент выпуска это 0.2.5. Установка использует профиль pickle и /data/yam, требует около 4 МБ для бинарника и 56 МБ свободного резерва для следующих обновлений панели.
3. Нажми «Подключить официальный реестр», затем «Найти». Каталог может содержать пакеты для других платформ: совместимость с pickle проверяет YAM при составлении плана/установке.
4. Выбери пакет, проверь зависимости, установи. Для локальной установки нужен доверенный .yampkg до 32 МБ. Postinstall запускается от root. Разрешение конфликтующих замен и зависимостей Entware по умолчанию выключено.
5. Запусти doctor. Для последующих версий менеджера используй «Обновить YAM»: подпись обновления проверяет штатный CLI. Снимки перед обновлением находятся в /data/darkls-alice/yam2-backups; сохраняются два последних. При неудачном запуске возвращается бинарник; база сохранена для ручной диагностики, данные пакетов автоматически не откатываются.

YAM v2 — менеджер CLI без HTTP-демона. Команда для root-консоли:

```sh
/data/yam/bin/yam-run list
/data/yam/bin/yam-run doctor
```

## Совместимость

- Старый yamd (/data/quazar/yam), его /etc/init.d/S99yam и .yap остаются на месте. Они доступны через явно обозначенные разделы Legacy .yap / Legacy yamd. Датчики и прежние приложения продолжают использовать legacy API.
- .yap не превращаются в .yampkg автоматически. Штатного конвертера в YAM 0.2.5 нет.
- `service list` показывает декларации, но YAM 0.2.5 не запускает службы и не обеспечивает их автозапуск. Интеграция Luna с Mini 3 Pro этой сборкой не устанавливается.
- Новому CLI не нужен boot-hook: он запускается панелью по запросу. Отключать legacy yamd не требуется.
- Формат и пути пакетов, хеши файлов и транзакции проверяет официальный CLI. Панель использует массив аргументов без shell-интерполяции.

## Проверка сборки

Модульные тесты проверяют выбор ветки v2, параметры команд, проверку ключей/форматов, повтор установки после ошибки, сохранение старого бинарника и отказ от отката при временной недоступности метаданных GitHub. HTTP-тесты проверяют вход и запрет чужого Origin для новых маршрутов.

Для интеграционного теста с настоящим ARM64-бинарником YAM 0.2.5 установи Python zstandard и укажи `YAM2_QEMU` (qemu-aarch64-static) и `YAM2_BINARY` (официальный yam-aarch64-unknown-linux-musl), затем запусти `python -m unittest discover -s tests -p test_yam2.py -v`. Тест работает в отдельном временном корне: установка пакета, файлы, владелец, декларация службы, повреждение/починка ссылки, doctor и удаление. Это не замена проверке на физической колонке.

Доступ к живому официальному каталогу из среды сборки не подтверждён (ограничения сети). Подключение реестра и жизненный цикл локального пакета проверены на официальном ARM-бинарнике; поиск проверяется на колонке после установки.
