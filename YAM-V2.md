# YAM v2 в DARKLS Alice Panel 0.5.0

1. В панели открой «Обновления панели», проверь и установи 0.5.0. После перезапуска обнови страницу.
2. Открой «YAM v2» → «Установить актуальный YAM». На момент выпуска это 0.2.5. Установка использует профиль pickle и /data/yam, требует около 4 МБ для бинарника и 56 МБ свободного резерва для следующих обновлений панели.
3. При наличии прежнего yamd нажми «Завершить переход и убрать yamd». Затем нажми «Подключить официальный реестр», затем «Найти». Каталог может содержать пакеты для других платформ: совместимость с pickle проверяет YAM при составлении плана/установке.
4. Выбери пакет, проверь зависимости, установи. Для локальной установки нужен доверенный .yampkg до 32 МБ. Postinstall запускается от root. Разрешение конфликтующих замен и зависимостей Entware по умолчанию выключено.
5. Запусти doctor. Для последующих версий менеджера используй «Обновить YAM»: подпись обновления проверяет штатный CLI. Снимки перед обновлением находятся в /data/darkls-alice/yam2-backups; сохраняются два последних. При неудачном запуске возвращается бинарник; база сохранена для ручной диагностики, данные пакетов автоматически не откатываются.

YAM v2 — менеджер CLI без HTTP-демона. Команда для root-консоли:

```sh
/data/yam/bin/yam-run list
/data/yam/bin/yam-run doctor
```

## Переход с прежнего yamd

В версии 0.5.0 экранов и API Legacy нет. Данные устройства, датчики и диагностика не используют порт 8099. Свет, часы, Bluetooth и плеер работают через прямой локальный адаптер.

После установки рабочего YAM нажми «Завершить переход и убрать yamd». Кнопка проверяет `yam list`, отключает известный /etc/init.d/S99yam и прежний флаг webpanel/yamd_autostart, останавливает процессы runtime и переносит весь каталог /data/quazar/yam в /data/darkls-alice/archives/yamd-…/runtime. Загрузочный скрипт и флаг хранятся рядом с runtime, режим скрипта и пути — в /data/darkls-alice/data/yamd-retirement.json. Архив не зашифрован, но находится в приватном каталоге панели. Через файловый интерфейс или ADB его можно сохранить на ПК. Flash автоматически не освобождается, так как данные сохранены.

При ошибке шага переноса каталог и известный загрузочный скрипт возвращаются на место. Остановленные процессы автоматически не запускаются. Неизвестный скрипт или символьная ссылка требуют ручной диагностики; панель не перезаписывает их. Повтор завершённого перехода ничего не изменяет. При отключении питания используй журнал состояния и архив для диагностики; перенос каталога атомарный, но все шаги целиком не являются одной атомарной операцией.

Автоматического преобразования .yap нет; старые приложения перестают выполняться после завершения перехода. YAM 0.2.5 сохраняет декларации служб, но не запускает их. Luna не устанавливается. Root, прошивка и /data/yam не меняются при удалении старого runtime. Обычный возврат версии панели не восстанавливает архивный yamd.

## Проверка сборки

Модульные тесты проверяют выбор ветки v2, параметры команд, проверку ключей/форматов, повтор установки после ошибки, сохранение старого бинарника и отказ от отката при временной недоступности метаданных GitHub. HTTP-тесты проверяют вход и запрет чужого Origin для новых маршрутов.

Для интеграционного теста с настоящим ARM64-бинарником YAM 0.2.5 установи Python zstandard и укажи `YAM2_QEMU` (qemu-aarch64-static) и `YAM2_BINARY` (официальный yam-aarch64-unknown-linux-musl), затем запусти `python -m unittest discover -s tests -p test_yam2.py -v`. Тест работает в отдельном временном корне: установка пакета, файлы, владелец, декларация службы, повреждение/починка ссылки, doctor и удаление. Это не замена проверке на физической колонке.

Доступ к живому официальному каталогу из среды сборки не подтверждён (ограничения сети). Подключение реестра и жизненный цикл локального пакета проверены на официальном ARM-бинарнике; поиск проверяется на колонке после установки.
