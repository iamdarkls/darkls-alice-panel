# Исправления аудио и обновления yamd (0.3.1)

В «Настройки → Аудиоформаты» нажать «Установить аудио-FFmpeg». Сборка ARM64 скачивается отдельно из Xiragi/FFmpeg-Audio-Builds: проверяются SHA-256 GitHub, архитектура ELF и реальная конвертация на колонке. Нужны 60 МБ свободно в /data (включая резерв обновлений панели) и 90 МБ в /tmp на время установки. Сжатая копия занимает несколько МБ на flash; исполняемый файл ~13 МБ находится в /tmp. На /system ничего не записывается. После перезагрузки файл автоматически восстанавливается из сжатой копии. Совместимость этой сборки FFmpeg с конкретной прошивкой проверяется установщиком, а не предполагается по модели.

Панель обновляет только старый демон yamd из релизов v0.1.x с нужным бинарником и SHA256SUMS. Ветка yam-v0.2.x — новый CLI с другой архитектурой; миграция на него этим обновлением не выполняется. Существующие пакеты и настройки демона сохраняются в резервной копии перед заменой.

GitHub Actions проверяет исходники, формирует приложение/компактный манифест и публикует Releases при изменении версии в app/DARKLS_VERSION. Существующий релиз не перезаписывается. Источник в панели остаётся releases/latest/download/update.json. Не выполнять старые инструкции установки 0.2.0 повторно.

## Установить с Windows

1. Распаковать ZIP целиком в Downloads/DARKLS-Update.
2. Открыть PowerShell в папке с upgrade.ps1 и выполнить:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\upgrade.ps1
```

Адрес по умолчанию 192.168.50.168; ADB ищется в Downloads/platform-tools/adb.exe. Иные значения: -DeviceIp и -AdbPath.

Перед переключением версии установщик создаёт копию настроек, включая секреты, и скачивает в Documents/DARKLS-Alice-Backups. Не публикуй эти архивы. Передаются только приложение и небольшой установщик; runtime не скачивается повторно. Пароль и автозапуск сохраняются. Успех: NATIVE_UPGRADE_OK. Открыть http://192.168.50.168:8770 и обновить страницу (на ПК Ctrl+F5).

Если обновление не проходит проверку запуска, установленный supervisor возвращает предыдущую сборку. При ошибке прислать вывод без токенов/паролей; не удалять runtime/data. Не выключать питание во время переключения версии. При недостатке места установка завершится до переключения.

## Обновления через GitHub

Репозиторий обновлений ещё НЕ создан и релиз НЕ опубликован. ZIP содержит скрипт, который загружает исходники отдельным коммитом в репозиторий и публикует app.tar.gz, update.json и source.zip. Git не требуется — используется GitHub CLI и Git Data API. Релиз ссылается на точный коммит исходников. API-ключ GitHub в панель не записывается.

Установить GitHub CLI (если нет):

```powershell
winget install --id GitHub.cli --exact
```

Заново открыть PowerShell, перейти в папку обновления, войти в свой GitHub:

```powershell
gh auth login
```

Создать **публичный** репозиторий и опубликовать эту сборку:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\publish-updates.ps1 -Repository iamdarkls/darkls-alice-panel -CreateRepository
```

Если репозиторий уже существует, убрать -CreateRepository. Скрипт не заменяет существующий релиз той же версии. app.tar.gz/source.zip содержат только публичные исходники, без данных с колонки, токенов и паролей.

После публикации скрипт настроит источник на колонке через ADB, если ADB доступен. Иначе вручную указать выведенный URL во вкладке «Обновления панели». Для указанного имени адрес будет:
https://github.com/iamdarkls/darkls-alice-panel/releases/latest/download/update.json

Нажать «Проверить». Версия будет 0.3.1 — это нормально, новая версия появится после следующей публикации. Автоустановка по умолчанию выключена; включается во вкладке обновлений. Каждые 6 часов supervisor проверяет версию и при включённом переключателе скачивает/устанавливает более новую. Предыдущая сборка сохраняется. Проверяется HTTPS, репозиторий, версия, размер и SHA-256; криптографической подписи отдельным ключом нет. Механизм не обновляет firmware, root, runtime, YAM или управляющий supervisor. Для следующего релиза нужен новый app.tar.gz и манифест с новой версией, размером и SHA-256.

«Вернуться к предыдущей версии» перезапускает панель и сохраняет пользовательские настройки. При возврате к 0.2.0 новые вкладки исчезнут, но настройки останутся в /data.

## Резервные копии

«Создать и скачать» передаёт архив браузеру; проверь его наличие в загрузках своего ПК/телефона. Дата в панели означает создание копии, а не подтверждение записи браузером на ПК. В /tmp хранится только последняя копия; после перезагрузки она исчезнет, скачанный файл остаётся.

По умолчанию включаются .panel_settings.json и снимки известных системных конфигураций: launch.json, launch-no-update.json, onboot/ADB скрипты, S99darkls/S99yam, версия firmware и сведения о маркерах. Секреты по отдельной галочке: токен Яндекса, конфигурация агента (с его токеном), сырой protobuf user_config.dat. Секретные архивы не зашифрованы. Пароль/сессии панели, runtime, NAND, пакеты YAM, музыка и анимации в копию не входят.

Восстановление проверяет структуру/хэши/JSON и заменяет только настройки панели и включённые токены. Системные снимки не применяются автоматически: их восстанавливают вручную после проверки. user_config.dat сохраняется как бинарный файл и никогда не записывается как обычный JSON. Перед восстановлением автоматически создаётся копия для отмены; скачай её по появившейся ссылке. Пароль текущей панели остаётся прежним. При смене токена Яндекса может потребоваться перезапуск службы панели.

## Диагностика

«Проверить всё» во вкладке диагностики: версия firmware, архитектура/ядро, uptime, RAM, свободное место, процессы Quasar/YAM/updatesd, маркеры ADB, init-файлы, ALSA и доступность quasar/scbh/YAM. Проверки сетевых адресов идут параллельно с тайм-аутом 5 секунд. HTTP 4xx/5xx показывает ответ сервера, но не успешную авторизацию. Отчёт не содержит токены и user_config.dat. Его можно скачать JSON. Полный отчёт не сохраняется на flash; записывается дата проверки.

## ChatGPT: что уже есть и что требует настройки

Новая вкладка — рабочая панель управления агентом Linux, а не установленный голосовой мост. Она сохраняет URL/токен, запрашивает реальный systemd-статус и отправляет start/stop/restart для одного заданного сервиса. Статус systemd не доказывает рабочий микрофон, звук или вход в ChatGPT.

Upstream https://github.com/rison1337/Alisa-ChatGPT-voice-assistant сейчас заявляет Лайт 1/2 и Станцию 2; Мини 3 Про в списке нет. Запуск заблокирован до аппаратной проверки совместимости. Не ставить LD_PRELOAD/аудиобиблиотеки от Лайт 2 вслепую.

На Linux-сервер можно скопировать папку linux-agent и выполнить:

```sh
sudo sh ./install-agent.sh
```

Это устанавливает ТОЛЬКО агент управления, не upstream/браузер/голосовой клиент. Сервис darkls-voice-agent слушает **127.0.0.1:8781**, конфигурация /etc/darkls-voice-agent.json (root:600), unit по умолчанию alisa-voice.service — его скрипт не создаёт. Сначала определить реальный systemd-unit установленного моста и вписать в конфигурацию; проверить `systemctl status ИМЯ.service`.

Для соединения колонки с VPS нужен частный туннель либо отдельный HTTPS reverse proxy к 127.0.0.1:8781. Не публиковать ADB 5555 и root SSH колонки. Не менять текущий nginx/Xray вслепую: параметры туннеля и домена настраиваются под сервер. Публичный HTTP панель отвергает; HTTP допускается по частному IP туннеля/локальной сети. Токен агента генерируется установщиком и хранится только в конфигурации. Для ввода в панель можно вывести его локально в SSH (не присылать в чат):

```sh
sudo python3 -c 'import json; print(json.load(open("/etc/darkls-voice-agent.json"))["token"])'
```

После проверки аудио Мини 3 Про установить compatibility_confirmed=true в конфигурации агента, перезапустить `sudo systemctl restart darkls-voice-agent` и подтвердить аппаратную проверку в панели. До этого доступны сохранение/проверка связи/остановка, а запуск и перезапуск закрыты на обеих сторонах.

Для дальнейшей настройки нужны характеристики Linux-сервера (ОС/RAM/свободное место, используемый nginx/Xray) и read-only данные ALSA/ELF колонки. Не отправлять пароли, ключи, токены, user_config.dat или полную конфигурацию VPN.

## Проверка сборки

29 серверных тестов: backup/restore/undo, неверные архивы/хэши, сохранение пароля и данных, голосовой агент/токен/ограничение запуска, настоящий HTTP с входом и CSRF, локальные shell/files/PTY, staging обновления и реальный supervisor rollback. DOM-тест новых кнопок и вкладок — Happy DOM. Проверка Python/JS/shell синтаксиса. ARM-колонка и Windows PowerShell в среде разработки недоступны — аппаратная проверка установки выполняется на устройстве пользователя.
