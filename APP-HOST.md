# Приложения YAM в панели 0.6.3

Открой «Приложения». Карточка содержит установленную версию, настраиваемое описание, службы пакета, их состояние, журналы и автоматически найденную ссылку на доступный веб-интерфейс. YAM 0.2.5 не сохраняет описание и веб-порт в установленной SQLite-базе: описание задаётся в карточке, адрес определяется по процессам и подсказкам пакета либо задаётся вручную. Формат пакета не изменяется.

## Запуск

- «Запустить», «Остановить», «Перезапустить» управляют объявленной в пакете службой. Произвольную команду через этот API передать нельзя.
- Автозапуск выключен по умолчанию. Включение переключателя сохраняет выбор для следующего запуска хоста; чтобы запустить сейчас, нажми «Запустить».
- «Остановить» действует в текущем сеансе; включённый автозапуск восстановит службу после следующей загрузки. Отключение автозапуска не останавливает уже работающий процесс.
- До восьми служб одновременно. Служба должна оставаться на переднем плане: самостоятельная демонизация/setsid не поддерживается.
- Используются массив exec, рабочая директория установленной версии, env, restart и oneshot из декларации YAM. `${YAM_ROOT}`, `${YAM_PKG}`, `${YAM_ETC}`, `${YAM_VAR}`, `${YAM_RUN}`, `${YAM_PLATFORM}` в аргументах и env раскрываются без shell. Эти переменные задаёт хост; переопределять их в env нельзя. Другие shell-подстановки и конвейеры не выполняются.
- `after: [network]` ждёт доступного интерфейса в таблице маршрутов; это не проверка Интернета. `quasar` ждёт maind. Имя службы текущего пакета или полное namespace/package/service ждёт работающей либо успешно завершённой службы. Зависимость автоматически не включается. Неизвестные и циклические зависимости остаются в ожидании с сообщением.
- Restart never/on-failure/always соблюдаются; oneshot после завершения автоматически не повторяется в текущем запуске хоста. Ошибки получают задержку 2–16 секунд; после пяти сбоев за минуту — 60 секунд. Есть ручной перезапуск.

При возврате к версии панели без хоста он останавливает управляемые службы. Настройки автозапуска сохраняются для следующего обновления.

Хост читает SQLite YAM только в режиме ro, понимает схему 0.2.5, проверяет путь executable внутри установленного пакета и не меняет флаг enabled в базе YAM. Службы работают от того же root, что и панель.

## Работа без ПК и обновления

Хост стартует при запуске нативной панели через существующий S99darkls, браузер не требуется. Отдельный init-hook и yamd не устанавливаются. Хост живёт отдельно от HTTP-процесса панели; обычный перезапуск панели его не останавливает. Если код хоста меняется, новая панель корректно останавливает прежний хост и запускает новый; восстанавливаются выбранные службы автозапуска, вручную запущенные без автозапуска нужно запустить снова.

Перед установкой/удалением пакетов, repair и обновлением CLI через панель запущенные приложения приостанавливаются, после операции возобновляются по актуальным декларациям. Настройки автозапуска удалённых служб очищаются. Для прямых внешних операций YAM хост учитывает lock-файлы и transaction.json, но для полного согласованного останова используй операции панели. При падении HTTP-процесса зависшая пауза снимается после освобождения блокировок; незавершённый transaction.json требует doctor/repair. Это не откат данных приложения.

## Проверка восстановления

Через 15 секунд после запуска хоста проверяются локальная панель, `yam list` и состояния выбранных служб. Дата, boot_id, результаты и объяснение ошибок хранятся в yam-recovery.json. Можно нажать «Проверить сейчас». Наличие процесса не гарантирует доступность приложения или его веб-интерфейса; для oneshot успешным считается код 0. Физическая перезагрузка колонки проверяется после установки пользователем; тесты воспроизводят перезапуск хоста с сохранённой конфигурацией.

## Данные и журналы

- /data/darkls-alice/data/yam-apps.json — автозапуск, описания, HTTP-порт и путь карточек.
- /data/darkls-alice/data/yam-recovery.json — последняя проверка загрузки.
- /data/darkls-alice/app-logs/ — по два файла до 256 КБ на службу; на экран читаются последние 32 КБ.
- /data/darkls-alice/app-host.log — запуск и ошибки хоста, ротация при следующем запуске.
- /tmp/darkls-apps-<hash>/ — блокировка и endpoint с секретом доступа, каталог 0700 и файл 0600. Хост слушает только 127.0.0.1 на случайном порту, запросы требуют отдельного секрета. Браузер работает через защищённые входом и Origin-проверкой маршруты панели /api/apps.

Данные приложений в YAM_ETC/YAM_VAR не включаются автоматически в существующую резервную копию панели. Журнал приложения может содержать его секреты; доступ к нему требует входа в панель. Новая база конфигурации пока не предназначена для ручного редактирования во время работы хоста.

PyYAML 6.0.3 включён в чистом Python с MIT-лицензией. Для деклараций используется SafeLoader, aliases запрещены, размер ограничен 32 КБ; отдельный pip не нужен.

## Совместимость UwU Eyes

Для vegych/uwu-eyes-panel в 0.6.1 добавлен отдельный ограниченный API экрана и временный токен в окружении. Его контракт и границы — в UWU-COMPAT.md. Наличие хоста служб само по себе не означает поддержку других Runtime API.

## Автоматические веб-ссылки (0.6.2)

Описание и ручные ссылки сохранены. По умолчанию адрес ищется автоматически по процессам пакета и проверяется по HTTP в фоне. Можно явно отключить ссылку. Подробности и ограничения: [WEB-PANELS.md](WEB-PANELS.md).
