# Автоочистка панели (0.6.4)

Включена по умолчанию. Нативный процесс панели запускает первый проход через минуту после старта, затем каждый час. Ещё один проход выполняется при проверке и перед установкой обновления через панель. Автоматический установщик в supervisor, установленном на колонке не заменяется обычным app-обновлением: для него действует фоновая почасовая очистка, а не новый непосредственный вызов перед apply.

Настройка и ручная кнопка находятся во вкладке «Обновления». Переключатель применяется после «Сохранить». Ручная кнопка работает и при выключенной автоматике. Результат записывается в cleanup-status.json; интерфейс показывает свободное место и фактически изменившееся значение свободных байтов ФС. На UBIFS сжатие и отложенное освобождение могут влиять на это число.

Удаляются только каталоги releases/VERSION-HASH с корректным DARKLS_VERSION и native.py, не используемые текущей/предыдущей сборкой или запущенными процессами, возрастом не менее часа. Неизвестные имена, символические ссылки и неоднозначные пути сохраняются. При ошибке чтения списка процессов или незавершённой проверке обновления проход пропускается. Удаляются также файлы config.json.*.new, update-status.json.*.new и cleanup-status.json.*.new старше суток — остатки прерванной атомарной записи. /tmp не обходится.

Проход использует update.lock — ту же блокировку, что обновление и откат. Резервные архивы (включая старый yamd), приложения и их данные, аудиофайлы, Python runtime и действующие журналы не очищаются. Текущая и предыдущая сборки сохраняются. Порог 52 МБ не уменьшается: если крупные архивы не были перенесены на ПК, их нужно перенести один раз вручную, чтобы установить это обновление.
