# UwU Eyes 1.11.4: ограниченный Runtime API

Панель 0.6.1 добавляет локальный API экрана для пакета vegych/uwu-eyes-panel. Это адаптер двух методов, не полная реализация yamd или Luna. Остальные пакеты не получают автоматически YAM_API_URL/YAM_API_TOKEN.

## Установка исправления

Обнови панель до 0.6.1, открой «Приложения» и перезапусти службу UwU Eyes. В карточке появится отметка «адаптер экрана». Затем открой http://192.168.50.168:1213/ (порт по умолчанию из README пакета). Если приложение по-прежнему завершается, посмотри новый журнал: ошибка отсутствующих переменных должна смениться результатом проверки API/оборудования. Физический экран проверяется на колонке после обновления.

## Контракт

Для службы этого пакета хост создаёт отдельный случайный токен и передаёт URL http://127.0.0.1:<случайный-порт>/api и токен через окружение. Токен живёт только в памяти и не возвращается в статусе служб. После остановки он отзывается. Пароль/сессия панели не используются.

Поддерживаются:

- GET /api/device с X-YAM-Token: model=yandexmini_3_pro, features=[display.clock.segment.v1], только если обнаружены все 36 доступных для чтения/записи узлов pickle:white:clock*. При отсутствии узлов capability не объявляется.
- POST /api/clock с JSON {"segments":{"A0":140,"H3":0}}: только A–H × 0–3, DEGREE, DH, DL, DM и целые значения 0–255. Произвольные пути, команды и другие устройства недоступны.
- POST /api/clock с JSON {"off":true}: возврат сохранённых яркостей и выбранных LED triggers после первого кадра через API.

API слушает только IPv4 loopback, требует токен и отклоняет browser Origin. Тело до 4096 байт. Одновременно через адаптер экраном владеет одна служба. Неподдерживаемые методы возвращают 404. Это не имитация возможностей без оборудования.

Сам UwU Eyes, согласно приложенному README, также умеет писать экран напрямую и закреплять его монтированиями. Адаптер этого не делает: он обеспечивает обнаруженный контракт и резервный путь /clock. Нельзя одновременно запускать другие рисующие на экране приложения. Для UwU Eyes время штатного завершения увеличено до 10 секунд, чтобы дать приложению снять собственные монтирования; за его механизм очистки отвечает сам пакет.

## Как получен контракт

Загруженный владельцем ELF AArch64 uwu-eyes 1.11.4 исследован статически и не запускался. SHA-256: 686623fd1c1f04d66f5fd32a873aa3eb35f2130ca34c4194b7cfba553a4867df. Бинарник в репозиторий не включён.

Из Go pclntab восстановлены main.connect, main.(*client).call и main.run. main.connect читает YAM_API_URL и YAM_API_TOKEN, принимает HTTP loopback. main.(*client).call передаёт X-YAM-Token. Все прямые вызовы этой функции из .text найдены в main.run: 0x292928 (GET /device), 0x2945fc (POST /clock, off=true), 0x29483c (POST /clock, segments). Проверка features ищет display.clock.segment.v1; model и features декодируются в структуру deviceInfo. Работа с sysfs видна в main.(*drawer).write и функции определения layout.

## Проверки

Тесты используют временные LED-файлы и собственный маленький тестовый процесс, а не загруженный ELF. Проверены точные JSON/HTTP формы, отсутствие ложной capability, валидация сегментов, возврат яркостей/triggers, разделение владельцев, запрет чужих токенов и Origin, отзыв токена даже при ошибке восстановления и передача окружения через реальный хост служб. Это проверяет адаптер, но не анимации на физической колонке.
